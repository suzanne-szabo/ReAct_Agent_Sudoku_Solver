# Functional Specification — `sudoku_agent.logic`

Status: **Draft v1 — awaiting orchestrator review**
Parent: `specs/architecture.md` §4.4, §7. Uses the vendored `proplogic` package
(architecture §4.3) without modifying it.

## 1. Purpose

`SudokuKB` is the propositional knowledge base the agent queries. It combines:

- a **rule layer** generated by the application from the current board, which
  encodes the Sudoku "physics"; and
- an **agent layer** of facts and rules the agent has told it.

It answers three-valued queries, refuses updates that would make the KB
inconsistent, and keeps the agent layer in step with undo.

## 2. Vocabulary and syntax

- **Cell variables:** `v{r}{c}{d}` (for example `v537`) means "row r, column c
  holds digit d", where r, c and d are each in 1–9.
- **Reserved form:** any symbol matching `v` followed by exactly three digits is
  a cell variable. If any of those digits is `0`, the symbol is invalid
  (`INVALID_SYMBOL`). Symbols like `v5370` or `vx` are ordinary agent symbols.
- **Other symbols:** the agent may use any other valid `proplogic` symbol (for
  example `pair_r1`) as its own helper proposition.
- **Formula syntax:** the full `proplogic` syntax: `~ ! & | -> <->`, the words
  `NOT AND OR IMPLIES IFF` (case-insensitive), and parentheses, with the
  `proplogic` precedence.
  - A malformed formula is rejected with `PARSE_ERROR` and the parser's message.
  - Formulas longer than 500 characters are rejected with `TOO_LONG`. This
    guards against the exponential growth of CNF conversion.

## 3. Rule layer (application-owned)

The rule layer is generated from a board snapshot by `rebuild(board)` and
whenever the KB is constructed. Let `E` be the board's empty cells and
`cand(x)` be `board.candidates(x)`.

1. **Cell has a digit.** For each x in E: the clause `v_x1 | v_x2 | … | v_x9`.
2. **Eliminated digits.** For each x in E and each digit d not in `cand(x)`:
   the fact `~v_xd`.
3. **Cell has at most one digit.** For each x in E and each pair a<b in
   `cand(x)`: the clause `~v_xa | ~v_xb`.
4. **Each missing digit appears in each unit.** For each row, column and box U,
   and each digit d not already present in U: the clause `OR of v_xd for every
   x in E∩U`.
5. **Each missing digit appears at most once per unit.** For the same U and d,
   and each pair x<y of cells in E∩U with d in both `cand(x)` and `cand(y)`:
   the clause `~v_xd | ~v_yd`.
6. **Filled cells are known.** For every filled cell (r, c) holding d, the rule
   layer is defined to include `v_rcd` and `~v_rce` for every e ≠ d.
   - *Performance note (not a behavior difference):* these facts are
     materialized only for filled-cell variables that occur in the agent layer
     or in the current query. This keeps the clause set and the DPLL recursion
     depth small.

**Key property (R\*):** the rule layer is satisfiable **exactly when** the
current board has at least one valid completion. A satisfying assignment of the
cell variables corresponds one-to-one to such a completion. As a result:

- for a puzzle with a unique solution and no wrong placements, every
  cell-variable query is answered `ENTAILED` or `CONTRADICTED`, never
  `UNRESOLVED`; and
- after a wrong placement, the rule layer becomes inconsistent.

The agent can never remove or alter the rule layer.

## 4. Agent layer

An ordered list of entries `(depth, formula)`. Here `depth` is the board's
undo-stack depth at the moment the formula was told.

## 5. Interface

```python
class Answer(Enum):
    ENTAILED = "entailed"
    CONTRADICTED = "contradicted"
    UNRESOLVED = "unresolved"

@dataclass(frozen=True)
class TellResult:
    accepted: bool
    reason: str | None       # None | PARSE_ERROR | INVALID_SYMBOL | TOO_LONG | INCONSISTENT | KB_INCONSISTENT
    message: str

@dataclass(frozen=True)
class AskResult:
    accepted: bool
    answer: Answer | None    # None when not accepted
    reason: str | None       # None | PARSE_ERROR | INVALID_SYMBOL | TOO_LONG | KB_INCONSISTENT
    message: str

class SudokuKB:
    def __init__(self, board: Board) -> None
    def rebuild(self, board: Board) -> None
    def is_consistent(self) -> bool
    def tell(self, formula: str) -> TellResult
    def ask(self, formula: str) -> AskResult
    def clear_agent_facts(self) -> int            # returns the number removed
    def rollback_to(self, depth: int) -> int      # returns the number removed
    def agent_facts(self) -> tuple[tuple[int, str], ...]
```

`SudokuKB` reads the board it is given but never mutates it. It keeps its own
reference to the board for `depth` and for filled-cell values.

### 5.1 `rebuild(board)`

Regenerates the rule layer from `board` and leaves the agent layer untouched.
The tool layer calls it after every accepted placement and after every accepted undo.

### 5.2 `is_consistent() -> bool`

Whether rule layer ∧ agent layer is satisfiable. By R\*, if the agent layer is
empty, this is `True` exactly when the board can still be completed.

### 5.3 `tell(formula) -> TellResult`

Checks, in order. Any rejection leaves the KB unchanged:

1. `TOO_LONG`, `PARSE_ERROR`, `INVALID_SYMBOL` — as in §2.
2. `KB_INCONSISTENT` — the KB is already inconsistent before this tell. The
   message tells the agent to undo or clear.
3. `INCONSISTENT` — adding the formula would make the KB unsatisfiable.

Otherwise, `(board.depth, formula)` is appended to the agent layer and the
result is `accepted=True`. Telling a formula string that is already present
(compared exactly) is accepted and not stored twice.

### 5.4 `ask(formula) -> AskResult`

1. `TOO_LONG`, `PARSE_ERROR`, `INVALID_SYMBOL` → `accepted=False`.
2. If the KB is inconsistent → `accepted=False, reason="KB_INCONSISTENT"`.
   Classically, an inconsistent KB entails everything, so no answer is given.
3. Otherwise `accepted=True` and:
   - `ENTAILED` if KB ⊨ q (that is, KB ∧ ¬q is unsatisfiable);
   - `CONTRADICTED` if KB ⊨ ¬q;
   - `UNRESOLVED` otherwise.

`ask` never changes the KB.

### 5.5 `clear_agent_facts()`

Empties the agent layer and returns how many entries were removed. The rule
layer is unaffected.

### 5.6 `rollback_to(depth)`

Removes every agent entry whose recorded depth is **greater than** `depth`, and
returns the count. The tool layer calls it with the board's new depth after an
accepted undo.
- Entries told at the undone depth or earlier are kept.
- `depth` must be an `int` ≥ 0; otherwise the call raises `ValueError` or `TypeError`.

## 6. Non-functional requirements

- **Performance:** on each bundled puzzle (easy, medium and hard), from the
  initial board, a single `ask` of a cell variable completes in **≤ 3 s** on
  the development machine. (Benchmark during design: ≤ 0.7 s.)
- **Recursion:** `proplogic`'s DPLL recurses once per assigned symbol, so
  `SudokuKB` must ensure the recursion limit is high enough for the largest
  rule layer. It restores the previous limit afterward.

## 7. Test obligations (black-box)

- **Rule layer and R\*:** on the bundled easy puzzle, a known solution digit is
  `ENTAILED`, a wrong digit for the same cell is `CONTRADICTED`, and a given
  cell's own digit is `ENTAILED`. `is_consistent()` is `True` initially.
- **Wrong placement:** after placing a non-conflicting wrong digit and calling
  `rebuild`, `is_consistent()` is `False`, and `ask` returns `KB_INCONSISTENT`.
- **Three-valued answers:** with a helper symbol, `ask("p")` on an empty agent
  layer is `UNRESOLVED`; after `tell("p")` it is `ENTAILED`; and `ask("~p")`
  is then `CONTRADICTED`.
- **Tell rejections:** each code, with the KB unchanged afterward (`agent_facts()`
  is identical and earlier answers are unchanged). An inconsistent tell such as
  `"v111"` on a cell whose solution is not 1 is rejected.
- **Duplicate tell** is stored once.
- **`clear_agent_facts`** removes the agent layer only; rule-based answers are unchanged.
- **`rollback_to`:** facts told at depths 0, 1 and 2, then `rollback_to(1)`,
  leaves the depth 0 and 1 facts.
- **Reserved symbols:** `v105` and `v000` give `INVALID_SYMBOL`; `v5370` is
  accepted as an ordinary symbol.
- **Performance** (marked `slow`): the §6 bound on the bundled hard puzzle.
